Panel A: Sorting Artifacts (Popping)

3DGS (Sorted α-Blending): $C = \sum_{i=1}^{N} c_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j)$ — order-dependent!
GES (Additive + Normalize): $C = \frac{\sum_{i} c_i \alpha_i}{\sum_{i} \alpha_i}$ — order-independent (sum is commutative).
Drag the camera angle slider. 3DGS must sort splats by depth — when the sort order flips, the color strip pops (sudden discontinuous change). GES uses additive accumulation, which is commutative — the result is identical regardless of splat order.

Panel B: Tile-Based Sorting

3DGS divides the screen into 16×16 pixel tiles and sorts Gaussians independently per tile. When two Gaussians overlap across a tile boundary, adjacent tiles may sort them in different orders, producing a visible seam. GES uses additive blending ($\sum c_i \alpha_i$) which is commutative — order doesn't matter, so no seams.

Panel C: Color Leaking & Depth Culling

SortFreeGS: $C = \frac{\sum_{i} c_i \alpha_i}{\sum_{i} \alpha_i + \epsilon}$ (Always leaks)
GES: $C_{GES} = \frac{W_S C_S + \sum_{i} \mathbb{1}(d_i < D_S + \delta) c_i \alpha_i}{W_S + \sum_{i} \mathbb{1}(d_i < D_S + \delta) \alpha_i + \epsilon}$
When a bright Gaussian is behind a solid opaque surfel (depth $D_S$), SortFreeGS blends them anyway, leaking color. GES introduces the indicator function $\mathbb{1}$ to explicitly cull fragments when $d_i > D_S + \delta$.

How to learn from this 3D demo:
Orbit the camera around the splats! 3DGS sorts transparent fragments based on the distance from their centers to the camera. As you orbit, watch the debug text above: when the camera crosses the threshold where the Blue splat becomes further away than the Red splat, Three.js swaps their render order. Because 3DGS relies on standard Alpha Blending, swapping the order drastically changes the blended color (popping). GES writes the Blue surfel to the explicit depth-buffer, so it perfectly occludes the Gaussians regardless of what order they are drawn!
